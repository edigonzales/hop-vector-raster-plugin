[[beispiele]]
== Beispielpipelines

Die Vorlagen liegen unter {repo}/tree/main/examples[examples im Repository].
Die hier angebotenen Downloads werden beim Handbuchbuild aus demselben Git-Stand übernommen.
Öffnen Sie die HPL-Datei in Hop GUI und setzen Sie die Parameter in der Ausführungskonfiguration.
Ausgabeordner müssen existieren; verwenden Sie neue Ausgabedateien oder ändern Sie bewusst die Overwrite-Einstellung.
Die migrierten Clip-/Reproject-Vorlagen starten mit Generate Rows → Raster Reader und schreiben
über einen Raster Writer. Die Statistik erhält eine Zeile pro Polygon aus Vector Reader → Raster Reader.
Ein abschliessender Select-Values-Schritt entfernt jeweils das Hilfs-Rasterfeld.
Die Generate-Rows-Zeile ist eine Eigenschaft dieser Vorlagen; ein Raster Reader kann auch selbst eine Zeile erzeugen.

=== Vektorkonvertierung

* link:downloads/cloud-output/vector-to-flatgeobuf.hpl[Vector Reader → FlatGeobuf herunterladen]
* link:downloads/cloud-output/vector-to-parquet.hpl[Vector Reader → Parquet herunterladen]

Parameter: `INPUT_VECTOR` (lokales `.shp`/`.gpkg`), `INPUT_LAYER` (leer: erster Layer), `OUTPUT_FILE`.
Beispiel: `/data/parcels.gpkg`, `parcels`, `/data/parcels.fgb`.
Der Reader benennt die Geometrie `geometry`; Attribute werden weitergereicht.
FlatGeobuf verwendet den räumlichen Index und lehnt NULL/EMPTY ab. Parquet verwendet GEOMETRY, GZIP und 128-MiB-Row-Groups.
Für leere Quellen Typ/Dimension im Writer explizit einstellen; fehlende Dezimalmetadaten vor Parquet ergänzen.

=== Externer COG-Clip

link:downloads/raster-clip/clip-cog.hpl[Parametrisierte Clip-Pipeline herunterladen]

[cols="2,4",options="header"]
|===
|Parameter |Beispiel
|INPUT_RASTER |`https://files.geo.so.ch/ch.swisstopo.swissalti3d_2025.dtm/aktuell/ch.swisstopo.swissalti3d_2025.dtm.tif`
|BBOX_CRS |`EPSG:2056`
|MIN_X / MIN_Y |`2607400` / `1228400`
|MAX_X / MAX_Y |`2607500` / `1228500`
|NODATA |Leer: Metadaten übernehmen
|OUTPUT_FILE |`/data/solothurn-clip.tif`
|===

In der Clip-Vorlage steht *Bands (ALL or 1-based list)* (`bands`) auf `1`;
in der Statistikvorlage steht *band* auf `1`. Beides sind feste Einstellungen, keine variablen Parameter.

Die URL ist ein Beispiel, keine dauerhaft zugesicherte Datenversion. Dieselbe Pipeline akzeptiert lokale GeoTIFFs.
Sie schneidet genau ein Band auf dem Quellraster aus; sie erzeugt keine neue Auflösung.
Der eingebundene Raster Writer ergänzt `raster_output_file` und `raster_status = OK`.

=== Reprojektion und Auflösungsänderung

* link:downloads/raster-reproject/elevation.hpl[Höhenmodell]: vorgegebene Solothurn-Box, standardmässig 1-m-Zielraster.
* link:downloads/raster-reproject/multiband.hpl[Mehrbanddaten]: automatische Ausdehnung, BILINEAR, alle numerischen Bänder.
* link:downloads/raster-reproject/palette.hpl[Palettenbild]: NEAREST mit Erhalt von Indizes und Farbtabelle.

Die Parameter stehen jeweils in der HPL-Datei: `INPUT_RASTER`, `OUTPUT_FILE`, `TARGET_CRS`,
`PIXEL_SIZE_X`, `PIXEL_SIZE_Y` und gegebenenfalls `OUTPUT_NODATA`.
Für reine Auflösungsänderung `TARGET_CRS` leer lassen. Numerisches Beispiel: lokales Höhenmodell EPSG:2056,
Pixelgrössen `2`/`2`, neue Zieldatei. Für EPSG:4326 werden die Pixelgrössen in Grad angegeben, beispielsweise `0.00001`/`0.00001`.
Die automatische Ausdehnung folgt der Quelle; das Höhenmodell-Beispiel besitzt eine feste Box und verlangt dazu passende CRS-Einstellungen.

Bei Paletten muss ein Sentinel ein vorhandener, nicht gültig verwendeter Index sein, falls zusätzliche ungültige Bereiche entstehen.
BILINEAR wandelt Paletten zu RGBA16 um. Weitere Regeln stehen unter <<raster-reproject,Reproject / Resample>>.

=== Zonale Statistik

link:downloads/raster-stats/zonal-statistics.hpl[Vector Reader → Raster Zonal Statistics herunterladen]

Parameter: `INPUT_VECTOR`, `INPUT_LAYER`, `INPUT_RASTER`, `GEOMETRY_CRS`, `NODATA`.
`GEOMETRY_CRS` darf bei korrekter Geometry-SRID leer bleiben. Beispiel: Gebäude-Polygone EPSG:2056 und
`https://files.geo.so.ch/ch.swisstopo.lidar_2023.ndsm_buildings/aktuell/ch.swisstopo.lidar_2023.ndsm_buildings.tif`,
Band `1`, Statistiken `mean min max` (im Dialog erweitern, etwa um `stddev sum`).
Das Gebäude-nDSM beschreibt Höhen über Terrain; verwenden Sie seine Werte direkt.

Die Beispielpipeline liefert Ergebniszeilen zur Vorschau; sie schreibt keine neue Vektordatei.
Zum Speichern fügen Sie einen Vector Writer mit neuem Zielpfad hinzu.
Überprüfen Sie neben `raster_mean`, `raster_min`, `raster_max` stets `raster_count` und `raster_status`.
NULL-Statistikwerte bei `NO_VALID_PIXELS` sind keine Höhe null.

link:downloads/raster-values/clip-reproject.hpl[Raster Reader → Clip → Reproject → Writer herunterladen]

[[raster-cog-writer-beispiel]]
=== Raster als Cloud Optimized GeoTIFF schreiben

link:downloads/raster-writer/cog.hpl[Raster Reader → Raster Writer (COG) herunterladen]

Parameter: `INPUT_RASTER`, `OUTPUT_FILE`, `COMPRESSION` (`Deflate` als Standard, `JPEG` für
RGB-Byte-Bilder), `OVERVIEWS` (`AUTO`) und `OVERVIEW_RESAMPLING` (`AVERAGE`). Die Vorlage liest eine
lokale GeoTIFF-Datei oder ein öffentliches HTTP-COG und schreibt über *Output format* `COG` ein Cloud
Optimized GeoTIFF mit internen Overviews. Die JPEG-Qualität steht fest auf 75 und lässt sich im Dialog ändern.
Der Writer ergänzt `raster_output_file` und `raster_status`; ein abschliessendes Select Values entfernt
das Hilfsfeld. Verwenden Sie für eigene Testdaten mindestens 1024 Pixel Kantenlänge, damit Overviews entstehen.
Die installierte Prüfung kontrolliert die Struktur mit `scripts/check-cog-output.py`; mit GDAL-Unterstützung
(`GDAL_PREFIX`) läuft zusätzlich der GDAL-Validator `validate_cloud_optimized_geotiff.py`. Die Ausgabe
wird anschliessend nochmals über den Raster Reader gelesen.

=== Lokale Prüfung

`scripts/check-doc-examples.py` führt Clip und Statistik aus den echten HPL-Dateien mit kleinen,
lokal erzeugten Testdaten aus. Benötigt werden Java 21 einschliesslich `javac`, Python 3 und eine saubere,
entbehrliche Apache-Hop-2.19.0-Installation ohne bereits installierte Geometry-, Raster-Type- oder Vector/Raster-Plugins.
Das Skript installiert die Plugins in diese Testinstallation.
Bauen Sie zuerst die passenden Raster-Type- und Geometry-Artefakte sowie das Vector/Raster-ZIP;
siehe {repo}/blob/main/docs/dev-setup.md[Entwickleranleitung].
In `assemblies/assemblies-hop-vector-raster/target` muss genau ein Vector/Raster-ZIP liegen.
Setzen Sie `HOP_HOME`, `GEOMETRY_ZIP` und `RASTER_TYPE_ZIP` auf absolute Pfade und führen Sie vom Repository-Stamm aus:

[source,bash]
----
python3 scripts/check-doc-examples.py --hop-home "$HOP_HOME" --geometry-zip "$GEOMETRY_ZIP" --raster-type-zip "$RASTER_TYPE_ZIP"
----

Externe öffentliche COGs gehören wie bisher nicht zur verpflichtenden Prüfung; das lokal erzeugte
COG-Beispiel wird dagegen mit Strukturprüfung und, falls GDAL verfügbar ist, mit dem GDAL-Validator geprüft.
