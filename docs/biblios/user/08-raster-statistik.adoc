[[raster-statistik]]
== Raster Zonal Statistics (GeoTools)

Dieser Transform ergänzt pro eingehender Polygonzeile Rasterstatistiken.
Typische Pipeline: *Vector Reader → Raster Zonal Statistics (GeoTools) → Vector Writer*.
Er schreibt selbst keine Rasterdatei. Plugin-ID: `SOGIS_RASTER_ZONAL_STATS`.

=== Dialogansicht

Die schematische Ansicht zeigt eine ausgefüllte Konfiguration.
`[ ]` kennzeichnet ein ausgeschaltetes, `[x]` ein eingeschaltetes Kontrollkästchen;
`[ Wert v]` steht für ein Auswahlfeld. Ein leeres Eingabefeld übernimmt die in der Einstellungstabelle erklärte Vorgabe.

[source,text,role="gui-dialog"]
----
+==============================================================================+
| Raster Zonal Statistics (GeoTools)                                           |
| ============================================================================ |
| Transform name                         [ Gebäudehöhen berechnen ]            |
| Input raster                           [ ${INPUT_RASTER} ] [ Browse... ]     |
| Raster address from input field        [ ]                                   |
| Geometry field                         [ geometry v]                         |
| Explicit geometry CRS (empty: geometry SRID) [ EPSG:2056 ]                   |
| Band (1 based)                         [ 1 ]                                 |
| NoData override (empty: raster metadata) [ ]                                 |
| Output field prefix                    [ height_ ]                           |
| Statistics (mean min max sum stddev; count always included)                  |
|   [ mean min max stddev ]                                                    |
|                                                                              |
|                                                          [ OK ] [ Cancel ]   |
+==============================================================================+
----

Setzen Sie `INPUT_RASTER` auf das Gebäude-nDSM aus dem Beispiel.
Die Eingabezeilen liefern die Polygonspalte `geometry`; Ergebnisfelder erhalten das Präfix `height_`.

=== Einstellungen

[cols="2,1,4",options="header"]
|===
|Einstellung |Standard |Bedeutung
|Transform name |Von Hop vergeben |Name des Schritts.
|Input raster |Leer |Lokale GeoTIFF-Datei oder öffentliche COG-URL.
|Raster address from input field |Aus |Die Rasteradresse stammt aus dem benannten Feld.
|Geometry field |`geometry` |Hop-Geometry-Spalte mit Polygon/MultiPolygon.
|Explicit geometry CRS (empty: geometry SRID) |Leer |CRS der Polygone; sonst SRID ungleich null erforderlich.
|Band (1 based) |`1` |Zu analysierendes Band.
|NoData override (empty: raster metadata) |Leer |Ersetzt den deklarierten Sentinel.
|Output field prefix |`raster_` |Präfix aller angehängten Kennzahlen und des Status.
|Statistics (mean min max sum stddev; count always included) |`mean min max` |Feste Auswahl (keine Variablen) mit Leerzeichen, Komma oder Semikolon; `count` wird immer ergänzt.
|===

=== Auswahl der Pixel und Kennzahlen

Ein Pixel wird gezählt, wenn sein Zentrum vom Polygon überdeckt wird, einschliesslich Zentren genau auf der Grenze.
Löcher und MultiPolygone sind möglich. Ungültige oder gekrümmte Geometrien müssen vorgelagert behandelt werden.
Die Geometrie wird bei Bedarf als Kopie in das Raster-CRS transformiert; Originalgeometrie und Attribute bleiben erhalten.
Rasterwerte stammen aus der Originalauflösung, ohne Resampling.

NoData, Masken und nichtendliche Werte werden vor Scale/Offset ausgeschlossen.
Die Kennzahlen beziehen sich danach auf physikalische Werte. Nullwerte werden berücksichtigt.
`stddev` ist die Standardabweichung der Grundgesamtheit, nicht die Stichproben-Standardabweichung.
Flächengewichtung, ALL_TOUCHED, Perzentile und Quantile werden nicht angeboten.

=== Ergebnisfelder und Fehler

Die ausgewählten Kennzahlen erscheinen in angegebener Reihenfolge, danach `count`, falls noch nicht enthalten, und `status`.
`count` ist Hop Integer, die übrigen Kennzahlen sind Hop Number, `status` ist String.
Bei `prefix = height_` und `statistics = mean min max stddev` entstehen:

[source,text]
----
height_mean, height_min, height_max, height_stddev, height_count, height_status
----

[cols="2,3",options="header"]
|===
|Status |Ergebnis
|`OK` |Positive Anzahl gültiger Pixel und berechnete Kennzahlen.
|`EMPTY_GEOMETRY` |Null-/leere Geometrie; count 0, übrige Kennzahlen null.
|`NO_VALID_PIXELS` |Ausserhalb des Rasters, nur NoData oder kein erfasstes Pixelzentrum; count 0, übrige Kennzahlen null.
|===

Vorhandene Felder dürfen nicht mit den neuen Feldnamen kollidieren.
Technische Fehler werden über einen Error Hop behandelt oder stoppen den Transform;
sie werden niemals als erfolgreiche count-0-Zeile kaschiert.
Für HTTP-COGs gelten die Range-/Authentifizierungsgrenzen aus <<raster-clip,Raster Clip>>.
Leser schliessen bei Quellenwechsel, EOF, Fehler und Disposal.

=== Beispiel: Gebäudehöhen

Lesen Sie Gebäudegrundrisse aus einem GeoPackage mit `Geometry output field = geometry`.
Wählen Sie folgendes Raster und konfigurieren Sie Band 1, Präfix `height_`, Statistiken `mean min max stddev`:

[source,text]
----
https://files.geo.so.ch/ch.swisstopo.lidar_2023.ndsm_buildings/aktuell/ch.swisstopo.lidar_2023.ndsm_buildings.tif
----

Das Raster enthält Gebäudehöhen über Terrain. Verwenden Sie diese Werte direkt für die Statistik.
`height_mean` ist die mittlere gültige Rasterhöhe innerhalb des Polygons, keine automatisch ermittelte First-, Trauf- oder baurechtliche Höhe.
Die Beispieldaten wurden mit 0.25 m, EPSG:2056, Float32 und NoData -9999 beschrieben; eine `aktuell`-URL kann sich ändern.
