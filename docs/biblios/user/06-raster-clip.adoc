[[raster-clip]]
== Rasterwerte: Reader, Clip, Info und Writer (GeoTools)

Die <<dialog-legende,Dialoglegende>> gilt auch für diese Ansichten. Die Rasterdialoge besitzen
vertikal scrollbar angelegten Inhalt und editierbare Auswahlfelder. Die gemischte Gross-/Kleinschreibung
der Labels entspricht der aktuellen GUI. Pfade und Transformnamen in den Skizzen sind Beispiele.

[[raster-reader]]
=== Raster Reader (GeoTools)

Plugin-ID: `SOGIS_RASTER_READER`.

[.gui-mockup]
----
+-------------------------------------------------------------------------------------+
| Raster READER (GeoTools)                                                            |
+-------------------------------------------------------------------------------------+
| Transform name                                      [ Beispiel READER ]             |
| Local GeoTIFF / public COG URL    [Value / Variable v] [terrain.tif] [Browse...]        |
| Reader output field               [ raster ]                                            |
|                                                                                     |
|                                                                   [ OK ] [ Cancel ] |
+-------------------------------------------------------------------------------------+
----

Raster Reader erzeugt einen typisierten Hop-Rasterwert aus einer lokalen GeoTIFF-Datei oder einer öffentlichen HTTP/HTTPS-COG-Adresse.
Im Modus *Value / Variable* wählen Sie über *Browse* eine lokale TIFF-Datei oder tippen eine öffentliche COG-URL ein.
Im Modus *Input field* enthält eine Eingabespalte pro Zeile den lokalen Pfad oder die URL. Ohne vorgelagerte Eingabe erzeugt der Reader eine Zeile; mit Eingabe ergänzt er jede Zeile.
*Reader output field* benennt die neue Spalte, in der der typisierte Rasterwert weitergereicht wird; Standard: `raster`.
Reader liest zunächst Metadaten, nicht den vollständigen Pixelbestand.

[[raster-clip-dialog]]
=== Raster Clip (GeoTools)

[.gui-mockup]
----
+------------------------------------------------------------------------------+
| Raster CLIP (GeoTools)                                                       |
+------------------------------------------------------------------------------+
| Transform name                                      [ Beispiel CLIP ]        |
| Input raster field                                  [ raster v ]             |
| Output raster field (empty: replace input)          [ <leer> ]               |
| Clip method (POLYGON / BOUNDING_BOX)                [ POLYGON v ]            |
| geometry Field                                      [ geometry v ]           |
| explicit Crs                                        [ <leer> ]               |
| Bands (ALL or 1-based list)                         [ ALL ]                  |
| no Data                                             [ <leer> ]               |
| Use input fields for bounding box coordinates       [ ]                      |
| min X                                               [ <leer> ]               |
| min Y                                               [ <leer> ]               |
| max X                                               [ <leer> ]               |
| max Y                                               [ <leer> ]               |
|                                                                              |
|                                                            [ OK ] [ Cancel ] |
+------------------------------------------------------------------------------+
----

Raster Clip (`SOGIS_RASTER_VALUE_CLIP`) liest dieses Rasterfeld. Das leere Ausgabefeld ersetzt die Eingabe;
ein anderer Name ergänzt einen zweiten Rasterwert. Andere Attribute bleiben erhalten. Er schreibt keine Datei.

* Clip-Methode: `POLYGON` (Standard) oder `BOUNDING_BOX`.
* Polygonfeld: standardmässig `geometry`; dessen SRID wird verwendet, wenn *explicit Crs* leer ist.
* *explicit Crs*: GeoTools-CRS-Code, zum Beispiel `EPSG:2056` oder `2056`; reine Zahlen werden als EPSG-Code interpretiert. WKT wird nicht unterstützt.
* Bounding Box: minX/minY/maxX/maxY und ein explizites CRS; die Box wird aus diesem CRS ins Raster-CRS transformiert.
* Bänder: `ALL` (Standard) oder eine geordnete Liste ab 1, zum Beispiel `1 3`.
* NoData: optionaler Override; Integer-Messraster ohne Sentinel benötigen einen darstellbaren Wert.

Alle methodenspezifischen Felder bleiben sichtbar; die für die gewählte Clip-Methode unpassenden
Felder sind ausgegraut und nicht editierbar. Bei `BOUNDING_BOX` geben Sie das CRS in *explicit Crs*
und die vier Grenzen in minX/minY/maxX/maxY ein. Wenn *Use input fields for bounding box coordinates*
aktiviert ist, enthalten diese vier Felder stattdessen Eingabespaltennamen. Deren Werte werden pro Zeile
als endliche Zahlen gelesen. Ohne Häkchen sind es Zahlen oder Hop-Variablen. Der gemeinsame Schalter
ist anfangs ausgeschaltet.

Bei `POLYGON` wird *geometry Field* verwendet. Ist *explicit Crs* leer, wird die SRID der Geometrie
verwendet; ein eingetragenes CRS bestimmt stattdessen, wie ihre Koordinaten interpretiert werden.

Die Box wird vor dem Zuschnitt ins Raster-CRS transformiert und auf die überlappenden Quellpixel beschränkt.
Polygonmasken verwenden Pixelzentren inklusive Rand, berücksichtigen Löcher und MultiPolygone.
Ungültige/gekrümmte Geometrien müssen vorgelagert behandelt werden. Leere und vollständig disjunkte Clips sind Fehler.
RGB/RGBA bleibt bei vollständiger Bandauswahl Farbe; Polygonmasken verwenden Alpha. Teilmengen werden gegebenenfalls numerisch.
Paletten bleiben bei Zuschnitt erhalten; Polygonmasken benötigen einen gültigen NoData-Palettenindex.

[[raster-info]]
=== Raster Info (GeoTools)

[.gui-mockup]
----
+--------------------------------------------------------------------------------+
| Raster INFO (GeoTools)                                                         |
+--------------------------------------------------------------------------------+
| Transform name                                      [ Beispiel INFO ]          |
| Input raster field                                  [ raster v ]               |
| Metadata fields (width height crs bands)            [ width height crs bands ] |
| prefix                                              [ raster_ ]                |
|                                                                                |
|                                                              [ OK ] [ Cancel ] |
+--------------------------------------------------------------------------------+
----

Raster Info (`SOGIS_RASTER_INFO`) ergänzt ausgewählte Metadatenfelder mit einem Präfix.
Unterstützt werden genau `width`, `height`, `crs` und `bands`; andere Namen werden abgelehnt.
Breite/Höhe sind Integer, `crs` enthält das Koordinatenreferenzsystem als WKT und `bands` ist ein JSON-String.
Dabei werden keine Pixel berechnet.
Die Skizze zeigt die Defaults; mit dem Präfix `raster_` entstehen `raster_width`,
`raster_height`, `raster_crs` und `raster_bands`. Bereits vorhandene gleichnamige Felder sind Fehler.

`raster_bands` enthält ein JSON-Array mit einem Eintrag pro Band. Jeder Eintrag hat diese Schlüssel:

`band`:: Bandnummer ab 1.
`name`:: Name des Bands.
`dataType`:: Datentyp des Bands.
`noData`:: NoData-Wert; `null`, wenn keiner definiert ist. Endliche Werte sind JSON-Zahlen,
  nichtendliche Werte werden als Text (`"NaN"`, `"Infinity"` oder `"-Infinity"`) ausgegeben.
`scale` und `offset`:: Skalierung und Offset des Bands.
`color`:: Farbinterpretation des Rasters.
`alpha`:: `true`, wenn dieses Band das Alpha-Band ist, sonst `false`.

[[raster-writer]]
=== Raster Writer (GeoTools)

[.gui-mockup]
----
+------------------------------------------------------------------------------------+
| Raster WRITER (GeoTools)                                                           |
+------------------------------------------------------------------------------------+
| Transform name                                      [ Beispiel WRITER ]            |
| Input raster field                                  [ raster v ]                   |
| Output GeoTIFF path [ Value / Variable v ]         [ ${PROJECT_HOME}/result.tif ] [ Browse... ] |
| Output format (GEOTIFF / COG)                       [ GEOTIFF v ]                  |
| Compression                                         [ Deflate v ]                  |
| JPEG quality (1-100)                                [ 75 ]                         |
| Internal overviews (AUTO / NONE)                    [ AUTO v ]                     |
| Overview resampling (AVERAGE / NEAREST)             [ AVERAGE v ]                  |
| Overwrite existing files                           [ ]                                      |
| Result field prefix                                [ raster_ ]                             |
|                                                                                    |
|                                                                  [ OK ] [ Cancel ] |
+------------------------------------------------------------------------------------+
----

Raster Writer (`SOGIS_RASTER_WRITER`) schreibt einen Rasterwert als lokale GeoTIFF-Datei und ergänzt
`<prefix>output_file` sowie `<prefix>status = OK`. Standardpräfix: `raster_`.
Im Modus *Value / Variable* geben Sie einen festen lokalen Pfad ein oder wählen ihn mit *Browse...* aus;
der Ausgabepfad ist anfangs leer. Im Modus *Input field* enthält eine Textspalte pro Zeile den lokalen Zielpfad.
*Browse...* ist in diesem Modus deaktiviert. `outputField` bleibt der gespeicherte HPL-Metadatenname
für diese Moduswahl. *Overwrite existing files* erlaubt das Ersetzen vorhandener Ziele und ist standardmässig
ausgeschaltet. Quellen dürfen auch über Dateisystemaliasse nicht überschrieben werden. Alle Eingabeattribute
bleiben erhalten; Namenskollisionen mit den Ergebnisfeldern sind Fehler. Verwenden Sie bei mehreren Zeilen
unterschiedliche Zielpfade, sofern dieselbe Datei nicht bewusst wiederholt überschrieben werden soll.
*Result field prefix* benennt die beiden Ergebnisfelder: Bei `raster_` heissen sie `raster_output_file`
und `raster_status`. Standardpräfix: `raster_`.
*Compression* bietet `None` sowie alle Kompressionsarten des eingebundenen TIFF-Writers: `CCITT RLE`,
`CCITT T.4`, `CCITT T.6`, `LZW`, `JPEG`, `ZLib`, `PackBits`, `Deflate`, `EXIF JPEG` und `ZSTD`.
Standard ist `Deflate` (verlustfrei). Nicht jede Kompression passt zu jedem Rastertyp; insbesondere sind
JPEG-Verfahren verlustbehaftet und CCITT-Verfahren für spezielle 1-Bit-Bilder gedacht. Der Writer filtert
die Auswahl nicht nach Datentyp. Bei einer inkompatiblen Auswahl meldet der TIFF-Writer beim Ausführen einen Fehler.
*Output format* wählt `GEOTIFF` (Standard) oder `COG`. Ein COG erhält zusätzlich zur tiled GeoTIFF-Ausgabe
interne Reduced-Resolution-Subfiles (Overviews), die IFDs mit ihren Tag-Werten vor den Bilddaten, die
Datenreihenfolge kleinste Overview → grösste Overview → Hauptbild, einen GDAL-kompatiblen Ghost-Bereich
sowie Block-Leader und -Trailer. Die Georeferenz steht nur auf dem Hauptbild.
*Internal overviews* (`AUTO`/`NONE`) steuert die Overviews: `AUTO` halbiert die Auflösung, bis Höhe und
Breite höchstens 512 Pixel betragen; die letzte Stufe umfasst höchstens eine Tile-Zeile oder -Spalte.
*Overview resampling* mittelt mit `AVERAGE` (NoData-Werte werden ausgelassen) oder wählt mit `NEAREST`
Stichproben; Palettendaten verwenden immer `NEAREST`. Beide Overview-Felder sind nur bei `COG` aktiv.
COG unterstützt `None`, `Deflate`, `ZLib`, `LZW`, `ZSTD`, `PackBits` und `JPEG`.
JPEG ist auf 8-Bit-Raster mit einem numerischen Band oder drei RGB-Bändern beschränkt;
Alpha, Palette und 16-Bit-Daten werden mit einer Meldung abgelehnt. Dreikanalige Bilder verwenden
den YCbCr-Farbraum mit gemeinsamen Tabellen im `JPEGTables`-Feld und abgekürzten Tile-Streams —
dasselbe Layout, das GDAL und damit QGIS erzeugen und lesen.
*JPEG quality* (1–100, Standard 75) ist nur bei `COG` mit `JPEG` aktiv.
`EXIF JPEG` und die CCITT-Verfahren bleiben der normalen GeoTIFF-Ausgabe vorbehalten.
Bei verlustbehafteter Ausgabe bleibt die Overview-Kaskade verlustfrei, damit sich die
JPEG-Verluste nicht über die Stufen aufsummieren.
Overviews werden komprimiert in temporäre Nachbardateien geschrieben, während des Schreibens in das COG
übernommen und danach entfernt; der zusätzliche Platzbedarf entspricht ungefähr den Overview-Daten.
Im Hop-Loglevel *Basic* erscheinen Start, Schreibfortschritt in 10-Prozent-Schritten und Abschlussdauer.
Die Ausgabe verwendet 512 × 512 Pixel grosse Tiles und ab geschätzten 2 GiB Rohdaten BigTIFF;
mit *Output format* `COG` entsteht ein Cloud Optimized GeoTIFF.
Das Elternverzeichnis muss existieren. Fehler/Abbruch entfernen die temporäre Nachbardatei und erhalten ein bestehendes Ziel.

=== Auswertung und Fehler

Pixel werden erst von Writer oder Statistik angefordert. Pixel-Lesefehler erreichen deren konfigurierten Error Hop; ohne Fehlerbehandlung bricht der Lauf ab.
Fehlermeldungen enthalten Quelle und Operationskontext. Konfigurationsfehler werden bereits bei der jeweiligen Operation erkannt.

[[raster-cog]]
=== Öffentliche HTTP/HTTPS-COGs

Raster Reader akzeptiert direkte öffentliche COG-URLs. Server und Proxy müssen gültige
Byte-Range-Antworten mit HTTP 206 und passendem `Content-Range` liefern.
Ein Server, der stattdessen die vollständige Datei liefert, wird abgelehnt; es gibt keinen Voll-Download-Fallback.
Der Reader-Dialog bietet keine Konfiguration für Zugangsdaten oder eigene HTTP-Header.

[[raster-migration]]
=== Bestehende Dateipipelines migrieren

Die alten Datei-Transforms benötigen eine Migration:

[source,bash]
----
python3 scripts/migrate-raster-values.py old.hpl new.hpl
----

Das Skript erhält die alte Pipeline und schreibt eine neue. Für Clip/Reproject ergänzt es
Reader, Operation und Writer; für Statistik einen Reader vor der Operation.
Die alte Clip-Einzelbandauswahl wird als `bands` übernommen. Ein zusätzlicher Select-Values-Schritt
entfernt das Hilfs-Rasterfeld aus den Ergebniszeilen; konfigurierte Error Hops erhalten ebenfalls passende Bereinigung.
Für direkte Rasterwertketten können Zwischen-Writer und die zugehörige Bereinigung entfernt werden.
Verbinden Sie dann die Operationen über dasselbe Rasterfeld und entfernen Sie es erst nach dem letzten Verbraucher.
Ein <<rasterwerte-beispiel,Beispiel ohne Zwischendateien>> steht zum Download bereit.
